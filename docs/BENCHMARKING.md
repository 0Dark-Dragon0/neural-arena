# Autonomous Cognition Benchmarking Specification

Traditional AI benchmarks measure static knowledge retrieval or code syntax generation. While useful, these benchmarks do not capture how models behave as **autonomous decision-making agents** operating over time in stateful, multi-agent environments.

Neural Arena provides a **deterministic, domain-agnostic, runtime-based benchmarking framework**. By evaluating agents based on their interaction logs with the simulation engine, we can score decision quality, adaptation, consistency, and efficiency.

---

## 1. Benchmarking Metrics

The scoring engine, implemented in [BenchmarkScorer.ts](../src/lib/benchmark/BenchmarkScorer.ts), evaluates agents on five core metrics.

```
                       ┌─────────────────────────┐
                       │    Agent Scorecard      │
                       └────────────┬────────────┘
                                    │
          ┌───────────────┬─────────┴───────┬───────────────┐
          ▼               ▼                 ▼               ▼
    ┌───────────┐   ┌───────────┐     ┌───────────┐   ┌───────────┐
    │ Decision  │   │Consistency│     │Adaptation │   │ Latency   │
    │  Quality  │   │   Score   │     │   Score   │   │  (10ms)   │
    └───────────┘   └───────────┘     └───────────┘   └───────────┘
```

### A. Decision Quality ($DQ$)
Decision Quality represents the proportion of valid, rule-abiding actions generated by the model:
$$DQ = \frac{\text{Intents Approved}}{\text{Intents Approved} + \text{Intents Rejected}}$$

### B. Adaptation Score ($AS$)
The Adaptation Score quantifies how efficiently an agent recovers when its intent is rejected. When an action fails, Neural Arena applies progressive prompt corrections. Agents that correct their errors at lower correction levels receive higher scores:
$$AS = 1 - \frac{\text{Prompt Correction Triggers}}{\max(\text{Total Attempted Actions}, 1)}$$

### C. Consistency Score ($CS$)
Consistency measures pattern stability and rule adherence rate over time, calculated as the complement of the rejection rate:
$$CS = 1 - \frac{\text{Intents Rejected}}{\text{Intents Approved} + \text{Intents Rejected}}$$

### D. Hallucination Rate ($HR$)
Captures the frequency of syntax rejections, malformed payloads, or illegal actions:
$$HR = \frac{\text{Intents Rejected}}{\text{Intents Approved} + \text{Intents Rejected}}$$

### E. Latency ($L_{\text{avg}}$)
Average API response times in milliseconds, rounded to the nearest **10ms**:
$$L_{\text{avg}} = \text{round}\left( \frac{\sum \text{Latency of Approved Requests}}{\text{Total API Responses}}, 10 \right)$$

## 2. Core Scoring Implementation

Below is the complete typescript code from the [BenchmarkScorer.ts](../src/lib/benchmark/BenchmarkScorer.ts) engine:

```typescript
import { RuntimeEvent } from '../../dashboard/src/types';

export interface AgentBenchmark {
  agentIndex: number;
  modelFamily: string;
  providerType: string;
  decisionQuality: number;      // 0.0 - 1.0
  adaptationScore: number;      // 0.0 - 1.0
  consistencyScore: number;     // 0.0 - 1.0
  hallucinationRate: number;    // 0.0 - 1.0
  avgResponseTimeMs: number;
}

export interface BenchmarkResult {
  version: 1;
  id: string;
  domain: string;
  timestamp: string;
  durationMs: number;
  agents: AgentBenchmark[];
  system: {
    eventDensity: number;
    intentThroughput: number;
    correctionRate: number;
  };
  domainData?: Record<string, any>;
}

export class BenchmarkScorer {
  /**
   * Compiles event arrays into standard Benchmark results
   */
  public static calculate(events: RuntimeEvent[], domain: string): BenchmarkResult {
    const agentsMap = new Map<number, {
      approved: number;
      rejected: number;
      corrections: number;
      latencies: number[];
      model: string;
    }>();

    let totalTicks = 0;
    let totalEvents = events.length;
    let startTimestamp = events[0]?.simulationTimeMs || 0;
    let endTimestamp = events[events.length - 1]?.simulationTimeMs || 0;

    for (const event of events) {
      if (event.type === 'TICK_ADVANCED') {
        totalTicks++;
        continue;
      }

      // Check agent metrics
      if (event.data && typeof event.data.agentIndex === 'number') {
        const idx = event.data.agentIndex;
        if (!agentsMap.has(idx)) {
          agentsMap.set(idx, { approved: 0, rejected: 0, corrections: 0, latencies: [], model: 'unknown' });
        }
        const record = agentsMap.get(idx)!;

        if (event.type === 'INTENT_ACCEPTED') {
          record.approved++;
        } else if (event.type === 'INTENT_REJECTED') {
          record.rejected++;
        } else if (event.type === 'COGNITIVE_CORRECTION_APPLIED') {
          record.corrections++;
        } else if (event.type === 'PROVIDER_REQUEST') {
          record.model = event.data.model || record.model;
        } else if (event.type === 'PROVIDER_RESPONSE') {
          record.latencies.push(event.data.latencyMs || 0);
        }
      }
    }

    const agentsList: AgentBenchmark[] = Array.from(agentsMap.entries()).map(([idx, data]) => {
      const totalAttempts = data.approved + data.rejected;
      const totalResponses = data.latencies.length;
      const avgLat = totalResponses > 0
        ? data.latencies.reduce((a, b) => a + b, 0) / totalResponses
        : 0;

      return {
        agentIndex: idx,
        modelFamily: this.extractFamily(data.model),
        providerType: data.model.includes('/') ? data.model.split('/')[0] : 'local',
        decisionQuality: totalAttempts > 0 ? data.approved / totalAttempts : 1.0,
        adaptationScore: totalAttempts > 0 ? 1.0 - (data.corrections / totalAttempts) : 1.0,
        consistencyScore: totalAttempts > 0 ? 1.0 - (data.rejected / totalAttempts) : 1.0,
        hallucinationRate: totalAttempts > 0 ? data.rejected / totalAttempts : 0.0,
        avgResponseTimeMs: Math.round(avgLat / 10) * 10
      };
    });

    const totalApproved = Array.from(agentsMap.values()).reduce((sum, d) => sum + d.approved, 0);
    const totalCorrections = Array.from(agentsMap.values()).reduce((sum, d) => sum + d.corrections, 0);
    const durationMinutes = (endTimestamp - startTimestamp) / 60000 || 1;

    return {
      version: 1,
      id: crypto.randomUUID(),
      domain,
      timestamp: new Date().toISOString(),
      durationMs: endTimestamp - startTimestamp,
      agents: agentsList,
      system: {
        eventDensity: totalTicks > 0 ? totalEvents / totalTicks : 0,
        intentThroughput: totalApproved / durationMinutes,
        correctionRate: totalApproved > 0 ? totalCorrections / totalApproved : 0
      }
    };
  }

  private static extractFamily(model: string): string {
    const parts = model.split('/');
    const name = parts[parts.length - 1] || model;
    return name.split('-')[0].toLowerCase();
  }
}
```

## 3. Pluggable Domain Adapters

While the core benchmark results focus on general decision quality and adaptation parameters, domain-specific evaluation details are isolated into pluggable adapters.

### The Chess Adapter (`src/lib/benchmark/adapters/ChessAdapter.ts`)
The chess evaluation module processes the event log to compute game-specific features, appending them to `domainData` inside the benchmark payload:
1. **Material Balance**: Evaluates the captured values over time:
   $$\text{MaterialValue} = 9Q + 5R + 3B + 3N + 1P$$
   Balances are computed at each move tick to identify strategic dominance profiles.
2. **Positional Complexity**: Measures how many legal moves were available to the model at each turn. Low positional values suggest the agent was forced into reactive maneuvers, while high positional numbers suggest strategic initiative.
3. **Resignation & Timeouts**: Logs the cause of the game-over state to differentiate cognitive resignations from system timeout errors.

## 4. Visualizing Profiles in the Dashboard

The **Benchmark Panel** in the Mission Control dashboard converts these metrics into a radar chart to visualize agent performance profiles:

* **Balanced Profile**: Symmetrical polygon showing high decision quality, quick response times, and strong adaptation.
* **Deliberative Profile**: High decision quality and adaptation but higher latency (characteristic of reasoning models).
* **Speed Profile**: Fast throughput and low latency, but potentially smaller polygon due to occasional intent rejections.
